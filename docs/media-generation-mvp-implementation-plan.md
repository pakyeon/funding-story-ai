# 미디어 계획·생성 실행기 1차 MVP 구현 계획

## 1. 목표

승인된 `story-maker-worker` 상태를 생성 경계에서 검증하고, 로봇청소기 제품 사실을
`MediaFacts`로 정규화한 뒤 `StoryTemplate`과 `MediaProfile`을 결합해 동적인 `MediaPlan`을
만든다. 검증을 통과한 계획만 FastMCP를 통해 stateless 생성 실행기로 전달하고, 텍스트·
이미지·편집용 HTML·배포 가능 HTML을 하나의 실행 결과로 만든다.

이번 단계의 기준은 와디즈가 공개한 책임 경계와 실제 성공 페이지에서 관찰한 표현 규칙이다.
비공개 내부 구현과 동일하다고 주장하지 않으며, 영상 생성과 범용 제품군 일반화는 범위에서
제외한다.

## 2. 요구사항 분석

### 입력과 권위 경계

- 자동 생성 분기는 두지 않는다. 동일 revision의 요약을 사용자가 명시적으로 승인한
  `generation-ready` 상태만 dispatcher가 제출한다.
- 생성 경계는 승인 revision, 요약 version, brief digest, worker projection digest와
  source/evidence/asset 참조를 보존한다.
- 정상 입력에는 `conflicting` 상태가 존재할 수 없다. stale revision, digest 불일치,
  존재하지 않는 참조와 상충 상태는 LLM 호출 전에 거부한다.
- `unknown` 선택 정보는 한 번 안내한 뒤 생략할 수 있지만, 편집용 HTML에는 구성 양식이
  정의한 고정 placeholder를 표시한다. LLM이 placeholder 문구를 만들지 않는다.

### 구성 양식과 미디어 계획

- `StoryTemplate`은 설득 흐름·영역 순서·문체·HTML 골격을 소유한다.
- `MediaProfile`은 제품군 능력군·후보 슬롯·활성화 조건·수량·참조 정책을 소유한다.
- `ProductFacts`/`MediaFacts`는 개별 제품의 확인된 사실과 상태·근거·참조 자산을 소유한다.
- `MediaPlan`은 이번 실행에서 활성화된 슬롯·장면·근거·배치·미디어 종류를 소유한다.
- 기능 하나마다 이미지를 만들지 않는다. 같은 설득 목적과 장면을 공유하는 기능은
  `slot_grouping_key`로 병합한다.
- 성공 이미지 수는 활성·병합된 생성 가능 슬롯을 기준으로 동적으로 정한다. 권장 4~6개,
  절대 상한은 8개다.

### 모델과 실행 정책

- 의미 분해·능력군 분류와 장면 표현은 LLM을 사용할 수 있다.
- 승인 상태, 필수 정보, 사실 상태, 참조 존재 여부, 영역 순서, 수량 상한과 배포 가능 여부는
  결정적 규칙이 소유한다.
- 이미지 기본 모델은 Nano Banana 2(`gemini-3.1-flash-image`), 폴백은 Nano Banana 2
  Lite(`gemini-3.1-flash-lite-image`)다.
- 기본 모델은 최초 1회와 제한된 재시도 1회, Lite 폴백은 1회만 허용한다. 인증·권한·잘못된
  요청·안전 정책 거부는 같은 요청을 반복하지 않는다.
- 제품 외형을 표방하는 장면은 본체·도크·부속품 역할에 맞는 제공 참조 자산을 사용한다.
  차트·표·문제 상황처럼 제품이 없는 장면에는 제품 참조를 강제하지 않는다.
- 이미지 API 실호출은 MediaPlan 자동 평가 통과와 별도 승인된 실험 묶음 이후에만 한다.
  이번 단계 AI API 총예산은 ₩300,000이며 비용 계산·추적 코드는 공개 제품 패키지에 넣지
  않는다.

### HTML과 결과물

- 본문은 `width: 100%`, `max-width: 740px`, 종횡비 보존, 모바일 전환점 768px를 기본으로
  렌더링한다.
- `draft_html`은 고정 placeholder와 검토 상태를 포함하고, `publishable_html`은 필수 정보와
  생성 자산이 모두 유효할 때만 만든다.
- 최종 HTML에는 내부 평가 카드, 출처 디버그 패널이나 테스트 조작 UI를 넣지 않는다.
- Streamlit 코드는 `main`에 추가하지 않는다. 핵심 구현 완료 후 별도 UI 브랜치에서 최종
  HTML을 그대로 렌더링한다.

### 현재 코드에서 발견한 교체 대상

- 구성 양식의 `image_required`만으로 5~6개 이미지를 고정 생성한다.
- 참조 이미지가 없으면 첫 생성 이미지를 뒤 장면의 참조로 사용해 장면 반복을 유발할 수 있다.
- OpenAI `gpt-image-2`를 우선하고 Gemini를 폴백하는 과거 공급자 정책이 남아 있다.
- 이미지 프롬프트가 이미지 내부 문자를 전부 금지해 현재 결정과 다르다.
- 미리보기와 편집 HTML이 최대 860px이고, 검증용 도구막대·출처 필드를 함께 표시한다.
- FastMCP 요청이 brief와 단일 이미지 경로만 받아 승인 revision·projection을 검증할 수 없다.
- 의미 정규화와 미디어 계획은 평가 스크립트·데이터만 있고 제품 실행 노드가 없다.

## 4. 검증 결과

- 의미 정규화 각 64건: 개발 macro F1 `0.978`, 방어 `0.976`, holdout `0.994`,
  adversarial `1.000`; 네 split 모두 분해 F1 `1.000`이며 최종 gate를 통과했다.
- 방어 split은 64건 중 경계 거부 56건에서 모델을 호출하지 않았고, 허용 8건만 호출했다.
  adversarial split도 위조 참조 32건은 호출 전에 거부하고 prompt-injection 32건만 호출했다.
- MediaPlan은 제품 변형 64건과 방어 64건을 검증했다. 상충 8건은 계획 이전 계약에서
  거부했고 나머지는 기대 decision·활성·비활성·placeholder·누락 참조와 일치했다.
- 이미지 API를 호출하지 않는 adapter 테스트에서 4·6·8개 독립 슬롯, 참조 분리,
  1개 실패 격리, 기본 모델 재시도와 Lite 폴백을 확인했다.
- 전체 `pytest` 167건, 핵심 소스 8개 `mypy`, 전체 Ruff, `uv lock --check`,
  데이터 계약 validator와 CLI 도움말 검증을 모두 통과했다.
- 실제 Nano Banana 이미지 품질·지연·비용 평가는 아래 비차단 후속 항목처럼 별도 승인된
  실험 묶음에서 수행한다.

## 5. 현재 비차단 후속 자료

아래 자료는 해당 최종 평가 전에 필요하지만 A~D 구현 시작을 막지 않는다.

- 프로젝트 단위 전체 오케스트레이션 최종 홀드아웃 64개
- 반복 동작 미디어 단독 슬롯 50개 이상
- 실제 이미지·HTML 사람 평가 표본과 일정
