# 적응형 story-maker-worker 구현 계획

- 상태: 완료
- 기준 설계: [적응형 story-maker-worker 설계](./adaptive-conversation-worker-design.md)
- 구현 브랜치: 핵심 `main`, UI `feat/streamlit-demo`
- 적용 범위: 사용자 입력부터 승인된 FastMCP 생성 요청까지

## 1. 요구사항 분석

### 사용자 경험 요구사항

- [x] `질문 → 정보 보완 → 요약 → 승인 → 생성`을 필수 실행 흐름으로 정의한다.
- [x] 최초 입력에서 즉시 생성을 요청해도 필수 정보가 부족하면 질문하도록 정의한다.
- [x] 질문 내용·순서·묶음은 현재 대화와 누적 사실을 바탕으로 LLM이 결정하도록 정의한다.
- [x] 생성 직전에 현재 결정 사항을 요약하고 명시적 승인을 받도록 정의한다.
- [x] 자동 생성과 질문 건너뛰기를 생성 승인으로 취급하지 않도록 정의한다.
- [x] 사용자가 이전 답변을 수정하면 최신 값을 기준으로 다시 질문·요약하도록 정의한다.

### 상태·메모리 요구사항

- [x] 대화 원문과 생성 기준이 되는 구조화 사실을 분리하도록 정의한다.
- [x] 같은 `thread_id`의 상태를 LangGraph Checkpointer로 유지하도록 정의한다.
- [x] 초기 MVP에서는 장기 메모리와 별도 메모리 프레임워크를 제외하도록 정의한다.
- [x] 요약 이후 정보가 바뀌면 승인 버전을 무효화하도록 정의한다.

### 안전·통합 요구사항

- [x] 필수 필드 검사는 규칙으로, 의미 판단은 LLM으로 분리하도록 정의한다.
- [x] 승인된 요약 버전과 현재 버전이 일치할 때만 FastMCP 호출을 허용하도록 정의한다.
- [x] 승인 없는 MCP 호출은 평가 전체에서 0회여야 한다고 정의한다.
- [x] 기존 `story-maker` 실행기와 FastMCP 도구 계약은 유지하도록 정의한다.

## 2. 현재 구현과의 차이

- [x] 현재 worker가 호출자 전달 이력과 불리언 승인 플래그에 의존함을 확인한다.
- [x] 현재 LangGraph가 요청 단위 라우팅만 수행하고 세션 상태를 저장하지 않음을 확인한다.
- [x] 현재 의미 추출과 다음 질문 판단이 하나의 LLM 출력 계약에 결합됨을 확인한다.
- [x] 현재 질문 건너뛰기가 생성으로 이어져 새 요구사항과 충돌함을 확인한다.
- [x] 현재 생성 전 구조화 요약과 요약 버전 검증이 없음을 확인한다.

## 3. 구현 체크리스트

### A. 상태와 계약

- [x] `StoryWorkerState`에 메시지, 사실, 변경 이력, 질문 이력, 요약과 승인 상태를 정의한다.
  - 검증: 상태 계약 단위 테스트에서 초기값과 직렬화 가능한 값만 허용한다.
- [x] `FactPatch`, `TurnUnderstanding`, `QuestionPlan`, `StorySummary`,
  `ApprovalDecision` 구조화 출력 모델을 정의한다.
  - 검증: 정상·잘못된 payload에 대한 Pydantic 검증 테스트가 통과한다.
- [x] 기존 의미 슬롯과 새 구조화 사실 사이의 변환 경계를 정의한다.
  - 검증: 승인된 상태를 기존 `GroundedBriefBuilder` 입력으로 변환해 schema 검증을 통과한다.

### B. 결정적 상태 처리

- [x] 허용 필드와 연산만 반영하는 `apply_fact_patch` reducer를 구현한다.
  - 검증: replace·append·명시적 없음·잘못된 필드·이전 값 보존 테스트가 통과한다.
- [x] 필수 필드 존재 여부를 검사하는 노드를 구현한다.
  - 검증: 충분·부족·빈 값·명시적 없음 사례의 예상 누락 목록이 일치한다.
- [x] 사실 변경 시 기존 요약 승인을 무효화하고 요약 버전을 갱신한다.
  - 검증: 승인 뒤 수정한 테스트에서 MCP 호출이 차단된다.

### C. LLM 노드

- [x] `understand_turn`을 사실 변경안과 사용자 의도만 반환하도록 분리한다.
  - 검증: 가짜 LLM으로 추출·수정·모호한 지시 결과를 독립 평가한다.
- [x] `plan_next_questions`가 상태·누락 필드·질문 이력으로 질문을 생성하도록 구현한다.
  - 검증: 이미 해소된 질문을 반복하지 않고 필수 누락 필드를 포함한다.
- [x] `build_summary`가 확정 사실과 미확인 정보를 구분하도록 구현한다.
  - 검증: 입력에 없는 사실이 요약에 포함되지 않고 모든 필수 사실이 포함된다.
- [x] `classify_approval`이 승인·수정·거절·모호함을 구분하도록 구현한다.
  - 검증: 고정 문장 데이터셋의 기대 분류와 일치한다.

### D. LangGraph와 Checkpointer

- [x] 질문, 보완, 요약, 승인 상태를 조건부 edge로 연결한다.
  - 검증: 각 시나리오에서 방문 노드와 최종 단계가 기대값과 일치한다.
- [x] `thread_id` 기반 Checkpointer를 연결한다.
  - 검증: 새 worker 인스턴스에서 같은 `thread_id` 상태를 복구한다.
- [x] 새 세션과 완료·취소 세션의 수명주기 경계를 구현한다.
  - 검증: 다른 `thread_id` 사이에 메시지와 사실이 섞이지 않는다.

### E. 승인과 MCP 안전장치

- [x] 생성 전 요약을 사용자 응답에 포함하고 승인 대기 상태로 전환한다.
  - 검증: 필수 사실 충족 직후에도 MCP 호출 없이 요약·승인 요청만 반환한다.
- [x] 명시적 승인과 현재 요약 버전 일치 여부를 검사하는 guard를 구현한다.
  - 검증: 명확한 승인만 통과하고 모호함·거절·수정은 차단된다.
- [x] 승인된 상태만 기존 brief builder와 FastMCP 도구에 전달한다.
  - 검증: 허용 경로 1회 호출, 모든 비허용 경로 0회 호출을 확인한다.
- [x] 동일 승인 재처리의 중복 제출을 기존 멱등성 키로 방지한다.
  - 검증: 같은 thread와 승인 버전 재시도에서 동일 키를 사용한다.

### F. 공개 API와 문서

- [x] 세션형 `WorkerRequest`·`WorkerOutcome` 계약으로 공개 API를 갱신한다.
  - 검증: README 예제와 API 단위 테스트가 새 계약으로 실행된다.
- [x] 현재 아키텍처와 한국어·영어 README를 실제 구현 상태에 맞게 수정한다.
  - 검증: 문서의 단계·승인·메모리 설명이 코드와 일치한다.
- [x] 핵심 worker 완료 후 Streamlit 브랜치가 새 세션 API만 사용하도록 갱신한다.
  - 검증: UI 테스트에서 질문·요약·승인·결과 단계를 표현한다.

## 4. 평가 체크리스트

### 노드별 평가

- [x] 입력 이해: 사실 추출, 수정과 충돌 감지 결과를 기록한다.
- [x] 필수 정보 검사: 누락 탐지 재현율과 잘못된 누락 판정률을 기록한다.
- [x] 질문 계획: 관련성, 중복률, 맥락 반영과 묶음 적절성을 기록한다.
- [x] 상태 갱신: 최신 값 반영률과 폐기 값 재사용률을 기록한다.
- [x] 요약: 입력 충실도, 누락률과 환각 현상 발생률을 기록한다.
- [x] 승인 분류: 오승인율과 모호한 승인 차단율을 기록한다.
- [x] 상태 전이: 허용되지 않은 전이와 반복 전이 발생률을 기록한다.
- [x] 도구 경계: 승인 없는 MCP 호출 횟수를 기록한다.

### 전체 흐름 평가

- [x] 필수 정보 충족 뒤 요약 단계 도달률을 기록한다.
- [x] 반복 질문 없이 완료한 비율을 기록한다.
- [x] 수정된 최신 사실의 최종 반영률을 기록한다.
- [x] 시나리오별 생성까지 대화 턴 수를 기록한다.
- [x] 중단·재개 상태 복구율을 기록한다.
- [x] 전체 시나리오의 승인 전 MCP 호출이 0회인지 확인한다.

## 6. 발견 문제 및 계획 변경 기록

| 발견 시점 | 문제 | 영향 | 체크리스트 변경 |
|---|---|---|---|
| 착수 | 핵심 구현 대상은 `main`, Streamlit은 별도 브랜치임 | UI와 핵심 코드 혼입 가능 | 핵심 worker 검증 후 UI 브랜치 반영 순서를 명시 |
| 착수 | 기존 `skip_requested=True`가 생성 시작 조건임 | 명시적 승인 요구사항 위반 | 건너뛰기 생성 경로 제거와 회귀 테스트를 E 항목에 포함 |
| 상태 검증 | 질문 계획이 누락 필드를 빼면서 이미 제공된 필드를 다시 요청할 수 있음 | 반복 질문과 대화 품질 저하 | 제공 완료 필드 반복 차단 guard와 회귀 테스트 추가 |
| 평가 구현 | 체크포인터에 남은 이전 요약을 턴마다 다시 집계함 | 요약 노드 평가 건수 과대 계산 | 이번 턴의 `visited_nodes` 증가분으로 노드 실행을 집계하도록 수정 |

## 7. 최종 요구사항 대조

구현 완료 후 다음 표에 실제 평가 근거를 연결한다. 구현 전에는 결과를 기입하지 않는다.

| 원래 요구사항 | 구현 위치 | 검증 근거 | 결과 |
|---|---|---|---|
| LangGraph 기반 질문·보완·요약·승인 | `conversation.py` 조건부 그래프 | 단계 전이 12/12 | 통과 |
| 필수 필드만 규칙으로 판정 | `check_required_fields` | 누락 검사 6/6 | 통과 |
| 나머지 의미 판단은 LLM 사용 | 4개 구조화 LLM 노드 | 노드 계약 회귀 평가 | 통과 |
| 세션 문맥을 Checkpointer로 유지 | SQLite `SqliteSaver` | 새 인스턴스 복구 1/1 | 통과 |
| 장기 메모리는 초기 MVP에서 제외 | thread 범위 상태만 사용 | 장기 저장·검색 코드 없음 | 통과 |
| 자동 생성 없음 | 승인 guard 단일 생성 경로 | 즉시 생성 요청 시 도구 호출 0회 | 통과 |
| 명시적 승인 전 MCP 호출 차단 | `approval_guard` | 비승인 호출 0건 | 통과 |
| 노드별·전체 흐름 평가 | 평가 fixture·러너·결과 문서 | 4개 시나리오 12/12 전이 | 통과 |
